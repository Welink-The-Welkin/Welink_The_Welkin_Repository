# 快速开始

这是托盘右键 → **帮助** 子菜单的详细参考。第一次配置请按下面五步操作；已在使用，可直接跳到：[看文章](#收到提醒后去哪里看文章) · [测试后待看为空](#测试成功为什么待看还是空的) · [没收到提醒](#公众号发文了却没收到提醒) · [没收到邮件](#有弹窗为什么没邮件) · [重启后怎么办](#电脑重启后要重新设置吗)。

## 第一次使用：怎样收到第一篇文章？

先启动本机程序，再让监测服务通过隧道向它投递。只有监测服务实际投递了订阅号的新文章，本机成功解析、保存后，才会在「待看文章」里看到它；自检和 FeedWe 的系统测试都不能代替这一步。

### 前置条件

- Windows 10 / 11
- Python 3.8+（[下载](https://www.python.org/downloads/)）
- 一个邮箱（用于注册示例监测服务；是否接收邮件提醒可另行选择）

> **安装 Python 时建议勾选这两项**：
> - `Add python.exe to PATH` —— 方便在终端运行下面的 `python` 命令
> - `tcl/tk and IDLE` —— 桌面弹窗和「待看文章」窗口使用 tkinter
>
> 检查是否就绪：命令行执行 `python -c "import tkinter"`，没有任何输出就是正常的。

**关于 `.bat` 脚本**：双击即用，不需要手动配环境。脚本会按以下顺序自动找解释器，
找到的第一个能 `import tkinter` 的即被采用：

1. PATH 中的 `python`
2. Windows 自带的 `py` 启动器
3. `%LOCALAPPDATA%\Programs\Python\Python31x` 等常见安装位置

都找不到时会明确提示去哪装、勾什么，而不是闪一下就消失。

---

### 第 1 步：安装并设置回调密码

在项目目录运行 `pip install -e ".[tray,win]"`，安装托盘和开机自启所需的依赖。

**已有回调 token 就沿用，不要重新生成。** 仅在还没有 token 时运行 `python run.py --gen-token`，它会把新的回调密码写入 `secrets.local.json`。含 token 的完整回调地址只填到自己的监测服务后台，不要公开分享或截图。

### 第 2 步：自检，然后正式启动

1. 双击 **`自检.bat`** 或运行 `python run.py --test`。默认应看到示例弹窗、听到提示音；若已启用邮件，还会**真的发送一封测试邮件**。这只检查本机通知功能，不测试隧道或订阅，不写入待看文章，自检结束也不会继续接收回调。
2. 自检结束后，双击 **`启动.bat`** 正式启动；也可以运行 `python run.py --tray`，并保持这个命令行窗口开启。若程序已经运行，不要再启动一份。
3. 右键 Windows 任务栏通知区域的红底对勾图标 → **查看状态**，应显示「运行中」。若看不到图标，双击 `查看状态.bat` 检查是否显示「服务运行中」。这只确认本机程序在线，还要完成下面的订阅和隧道设置。

### 第 3 步：注册监测服务并添加公众号

微信公众号没有公开订阅接口，必须借助第三方服务来"盯号"。本项目默认用 [FeedWe](https://feedwe.top/auth/register)
作为示例，**但你可以用任何支持 webhook 的服务**（见 [PROVIDERS.md](PROVIDERS.md)）。

1. 打开监测服务网站，用邮箱注册并验证
2. 进入「订阅管理」，搜索并添加要盯的公众号，例如：
   - `上理大学生`（示例）
   - 你所在学院的团委号（学院号也经常发加分活动）
3. 给重点的号选最快档位（通常是 1 分钟档）

> 搜不到某个号时，试试完整全名。仍搜不到可在服务商页面点「反馈」让他们补充。

---

### 第 4 步：开隧道，拿到公网回调地址

监测服务在云端，它需要一个公网地址才能把消息推到你电脑。保持第 2 步启动的程序运行，在另一个终端操作。

这里有两条路，**先看清区别再选**：

| | Cloudflare 快速隧道 | Tailscale Funnel |
|---|---|---|
| 地址 | `xxx.trycloudflare.com` | `机器名.tailnet名.ts.net` |
| **普通重启后** | 重开隧道，去监测服务后台更新地址，保持隧道窗口开启 | 地址通常不变；分别确认本程序在运行、Tailscale 已连接 |
| 需要账号 | 不需要 | 需要（免费注册） |
| 需要域名 | 不需要 | 不需要 |
| 延迟 | 低 | 略高（走中继） |
| 启动窗口 | 要一直开着 | 后台常驻，可关窗口 |

只想先跑通，走 A。**不想每次重启都手动改后台，直接走 B。**

#### A. Cloudflare 快速隧道（最快跑通）

1. 生成隧道并打印回调地址：

   ```bash
   python start_tunnel.py
   ```

2. 第一次运行会提示没装 `cloudflared`，按提示安装：

   ```
   winget install --id Cloudflare.cloudflared
   ```

3. 装完重新运行，脚本会自动打印并保存地址：

   ```
   https://一串随机单词.trycloudflare.com/hook?token=你的token
   ```

把完整地址留给第 5 步。**隧道窗口要一直开着**；关掉就会断开。重新启动临时隧道后地址会变，要去监测服务后台更新。

#### B. Tailscale Funnel（固定地址，推荐）

首次配置好后，普通重启通常不用修改回调地址；本程序和 Tailscale 仍需分别保持在线。

1. **装 Tailscale**（管理员终端）：

   ```powershell
   winget install --id Tailscale.Tailscale
   ```

2. **登录一次**（管理员终端，会弹浏览器让你授权）：

   ```powershell
   & "C:\Program Files\Tailscale\tailscale.exe" up
   ```

   用 Google / Microsoft / GitHub 账号都行，注册免费。授权后这个终端窗口可以关掉。

3. **在 Tailscale 后台开两样东西**（打开 <https://login.tailscale.com/admin/dns>）：

   - **MagicDNS** —— 打开
   - **HTTPS Certificates** —— 点 `Enable HTTPS...` 打开

   请让管理员在[访问策略](https://login.tailscale.com/admin/acls)中**保留现有规则**，确认仅给运行本程序的设备授予 `funnel` 权限。若已有相应授权，无需修改；不要整份替换策略，也不要为方便测试而扩大到所有成员。

4. **开 Funnel**（管理员终端）：

   ```powershell
   python start_tunnel.py --mode funnel
   ```

   脚本会自己跑 `tailscale funnel --bg --https=443 http://127.0.0.1:8765`，
   然后打印：

   ```
   https://你的机器名.你的tailnet名.ts.net/hook?token=你的token
   ```

   > 为什么是 `--https=443`：Funnel 只允许 **443 / 8443 / 10000** 三个公网端口，
   > 而你本地程序在 8765。这行参数就是把 443 映射到 8765，必须写。

把打印的完整地址留给第 5 步。只要域名和 token 没有变化，普通重启后不必重新填写。

随时可以重新问出当前地址：

```bash
python start_tunnel.py --mode funnel --print-url
```

停止 Funnel：

```powershell
& "C:\Program Files\Tailscale\tailscale.exe" funnel --https=443 off
```

> Funnel 会把本机的回调端点公开到互联网。保管好含 token 的完整地址。

### 第 5 步：保存回调，等第一篇正式文章

1. 在监测服务后台打开「配置推送通知」→ **自定义 Webhook**。粘贴并保存第 4 步得到的完整地址（包括 `/hook?token=…`）。用普通回调地址即可。
2. 若使用 FeedWe，可点「发送测试消息」检查回调。后台显示投递成功，不代表本机应该弹窗；它发的是系统测试，不是订阅号文章。
3. 保持本程序和隧道在线。等订阅号实际发文、监测服务将新文章投递过来，再右键托盘图标 → **待看文章** → **刷新**。能看到该篇标题，才算收到了第一篇正式文章。

## 收到提醒后，去哪里看文章？

右键托盘图标 → **待看文章**，点 **刷新**，选中标题后点 **打开原文**。即使弹窗已消失，未读文章仍在清单中。打开原文不会自动移除它；看完后点 **标记已看**，才会从待看清单移除。

## 测试成功，为什么待看还是空的？

| 做了什么 | 结果说明什么 |
|---|---|
| 双击 `自检.bat` 或运行 `python run.py --test` | 只测本机通知功能：按配置弹窗、响铃，邮件已启用时也会真实发信。不会写入待看或更新「最近正式投递」。 |
| FeedWe 在普通回调上「发送测试消息」 | 程序识别 `accountName` 为 `FeedWe System Test` 的消息，不弹窗、不发邮件、不计入正式文章，也不更新「最近正式投递」；与标题是否命中关键词无关。 |
| 监测服务投递订阅号的正式新文章 | 本机成功解析、保存后，「查看状态」的「最近正式投递」会更新，新文章才会出现在「待看文章」。重复投递不会增加未读数。 |

要核对 FeedWe 的测试请求是否到过本机，默认配置下可在 `data/raw/` 查找测试时间对应的记录。测试成功但还没有正式投递时，待看为空是正常的，不必修改关键词。

## 公众号发文了，却没收到提醒？

1. 先到 **待看文章** 点 **刷新**。如果该篇在清单里，说明本机已经收到；去 **查看状态** 看「待派送」「派送失败」，并核对[弹窗配置](CONFIG.md#弹窗)。默认命中关键词逐篇提醒，未命中的新文章按公众号合并提醒，不一定每篇都单独弹窗。
2. 如果没有该篇，对照发文时间查看 **查看状态** 的「最近正式投递」「最近解析异常」，再用 **打开日志** 查同一时段的记录。日志中的「正式投递」会给出解析篇数和新收篇数；时间本身不能证明收到的是这篇文章。
3. 若没有这次投递记录，确认本程序在线、隧道连通，再去监测服务后台核对订阅的公众号、完整回调地址和实际投递结果。程序不会主动抓取公众号历史文章；上游没有投递，本机就不会有这篇。更多情况见[疑难排查](TROUBLESHOOTING.md)。

## 有弹窗，为什么没邮件？

弹窗和邮件是两个独立的通知渠道。右键托盘图标 → **查看状态** 看「邮件通知」：

- **未启用**：按[邮件通知配置](CONFIG.md#邮件通知)开启邮件、填写 SMTP 账号、邮箱授权码和收件地址；保存后退出并重新启动本程序。
- **已开启**：运行自检会真实发一封测试邮件。若提示发送失败，用 **打开日志** 查邮件错误；若提示发送成功，核对收件地址并检查垃圾邮件文件夹。

## 电脑重启后，要重新设置吗？

先确认**本程序**是否在运行：登录 Windows 后，在托盘点 **查看状态**，或双击 `查看状态.bat`。若未运行，双击 `启动.bat`；已运行不必重复启动。[开机自启](CONFIG.md#开机自启)只负责启动本程序，不代表隧道也连通了。

再右键托盘图标 → **打开回调地址文件**，看域名末尾来区分隧道：

- **`.ts.net`（Tailscale Funnel）**：另外在 Tailscale 客户端确认这台电脑显示已连接。原有 Funnel 配置、域名和 token 没有变化时，普通重启不用去监测服务后台改地址，也不用重新授权。
- **`.trycloudflare.com`（Cloudflare 快速隧道）**：重新运行 `python start_tunnel.py`，把它打印的新完整地址更新到监测服务的 Webhook 设置，**保持隧道窗口开启**。
- **没有地址文件**：先按第 4 步核对使用的是哪种隧道；尚未配置的，选择一种完成配置并保存回调。不要因为找不到文件就重新生成 token。
